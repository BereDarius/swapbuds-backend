# Release v0.12.0 - Dispute Resolution System

**Release Date**: November 22, 2025
**Version**: 0.12.0
**Release Type**: Minor Release

## Overview

Comprehensive dispute resolution system allowing users to report trade issues with admin intervention, full audit trails, and structured workflow for conflict resolution.

## Features

### Trade Dispute Management
- **File Disputes**: Users can report issues with trades
- **Dispute Reasons**: 6 predefined types (Item Not As Described, Not Received, Damaged, Communication Issues, Scam Attempt, Other)
- **Automatic Validation**: Only trade participants can file disputes
- **Duplicate Prevention**: One dispute per user per trade
- **Status Tracking**: OPEN → UNDER_REVIEW → RESOLVED/CLOSED

### Admin Dispute Workflow
- **Assignment System**: Admins assign disputes to themselves
- **Resolution Notes**: Detailed admin notes and resolution explanations
- **Trade Cancellation**: Resolving dispute automatically cancels trade
- **Close Without Resolution**: Option to close disputes

### Role-Based Access Control
- **Admin Guard**: Protects admin-only endpoints
- **isAdmin Flag**: New field on User model
- **Access Control**: Users see only their own disputes; admins see all

## API Endpoints

| Method | Endpoint | Description | Authorization |
| ------ | -------- | ----------- | ------------- |
| POST   | `/api/disputes` | Create dispute | Trade participant |
| GET    | `/api/disputes/me` | Get user's disputes | Authenticated |
| GET    | `/api/disputes/:id` | Get dispute details | Participant or admin |
| GET    | `/api/disputes` | Get all disputes (filterable) | Admin only |
| PATCH  | `/api/disputes/:id/assign` | Assign to admin | Admin only |
| PATCH  | `/api/disputes/:id/resolve` | Resolve with notes | Admin only |
| PATCH  | `/api/disputes/:id/close` | Close without resolution | Admin only |

## Technical Implementation

### Database Schema
```prisma
enum DisputeStatus {
  OPEN
  UNDER_REVIEW
  RESOLVED
  CLOSED
}

enum DisputeReason {
  ITEM_NOT_AS_DESCRIBED
  ITEM_NOT_RECEIVED
  ITEM_DAMAGED
  COMMUNICATION_ISSUES
  SCAM_ATTEMPT
  OTHER
}

model Dispute {
  id              String        @id @default(cuid())
  tradeId         String
  filedById       String
  againstId       String
  reason          DisputeReason
  description     String
  status          DisputeStatus @default(OPEN)
  assignedToId    String?
  resolutionNotes String?
  resolvedAt      DateTime?
  createdAt       DateTime      @default(now())
  updatedAt       DateTime      @updatedAt
  
  trade           Trade         @relation(fields: [tradeId], references: [id])
  filedBy         User          @relation("DisputesFiled", fields: [filedById], references: [id])
  against         User          @relation("DisputesAgainst", fields: [againstId], references: [id])
  assignedTo      User?         @relation("DisputesAssigned", fields: [assignedToId], references: [id])
  
  @@unique([tradeId, filedById])
  @@index([status])
}

model User {
  // ... existing fields
  isAdmin         Boolean       @default(false)
}
```

### Services
- **DisputesService**: 8 methods for dispute lifecycle
  - `createDispute()` - Validate and create
  - `getUserDisputes()` - User's disputes
  - `getDispute()` - Access-controlled retrieval
  - `getAllDisputes()` - Admin with filtering
  - `assignDispute()` - Admin assignment
  - `resolveDispute()` - Resolve and cancel trade
  - `closeDispute()` - Close without resolution

### Guards
- **AdminGuard**: Checks `user.isAdmin` field, throws ForbiddenException if false
