# Release v0.6.0 - Trading System

**Release Date:** November 22, 2025
**Version:** 0.6.0
**Type:** Feature Release

## 🎯 Overview

This release introduces the complete Trading System, enabling users to propose, accept, reject, and cancel item trades on the SwapBuds platform.

## ✨ New Features

### Trading System

- **Trade Proposals**: Users can propose trades by offering one of their items in exchange for another user's item
- **Trade Management**: Full lifecycle management with status transitions (PENDING → ACCEPTED/REJECTED/CANCELLED)
- **Authorization**: Role-based operations (proposer can cancel, responder can accept/reject)
- **Atomic Updates**: Items automatically marked as TRADED when trade is accepted (transaction-safe)
- **Validation**: Comprehensive checks for ownership, availability, self-trading prevention, and duplicate proposals

## 🔌 API Endpoints

Six new REST endpoints added to the Trading System:

| Method | Endpoint             | Description                     | Authorization                 |
| ------ | -------------------- | ------------------------------- | ----------------------------- |
| POST   | `/trades`            | Create a new trade proposal     | Authenticated user (proposer) |
| GET    | `/trades/my-trades`  | Get all trades for current user | Authenticated user            |
| GET    | `/trades/:id`        | Get specific trade details      | Authenticated participant     |
| PATCH  | `/trades/:id/accept` | Accept a trade proposal         | Responder only                |
| PATCH  | `/trades/:id/reject` | Reject a trade proposal         | Responder only                |
| PATCH  | `/trades/:id/cancel` | Cancel a trade proposal         | Proposer only                 |

## 🏗️ Technical Implementation

### New Modules

- **TradesModule**: Complete NestJS module with service, controller, and DTOs
- **TradesService**: Business logic with validation and transaction handling
- **TradesController**: REST API endpoints with Swagger documentation

### DTOs

- `CreateTradeDto`: Validation for trade proposal creation
- `TradeResponseDto`: Structured response with nested user and item data
- `UpdateTradeStatusDto`: Status update validation

### Database

- Uses existing `Trade` model from Prisma schema
- Transaction support for atomic item status updates
- Relations: Trade → User (proposer/responder), Trade → Item (offered/requested)

## 📝 Business Rules

### Trade Creation

- ✅ User must own the offered item
- ✅ Both items must exist and be AVAILABLE
- ✅ Cannot trade with yourself
- ✅ Cannot create duplicate trade proposals
- ✅ Optional message (max 500 characters)

### Trade Acceptance

- ✅ Only the responder can accept
- ✅ Trade must be in PENDING status
- ✅ Both items marked as TRADED atomically
- ✅ Trade status updated to ACCEPTED
- ✅ Completion timestamp recorded

### Trade Rejection

- ✅ Only the responder can reject
- ✅ Trade must be in PENDING status
- ✅ Trade status updated to REJECTED

### Trade Cancellation

- ✅ Only the proposer can cancel
- ✅ Trade must be in PENDING status
- ✅ Trade status updated to CANCELLED
