# v0.5.0 - Likes & Comments

This release adds user engagement features to the SWAPBUDS platform, allowing users to like items and leave comments.

## New Features

### Likes Module

- Like/unlike items with a single click
- View likes count for any item
- Check if you've already liked an item
- See all users who liked an item (with avatars)
- Prevents duplicate likes with unique constraint

### Comments Module

- Create comments on items (max 1000 characters)
- View all comments for an item
- Edit your own comments
- Delete your own comments
- Get comment counts for items
- Comments include user info (username, avatar, timestamps)

## API Endpoints

### Likes

- `POST /api/items/:itemId/like` - Like an item (auth required)
- `DELETE /api/items/:itemId/like` - Unlike an item (auth required)
- `GET /api/items/:itemId/likes/count` - Get likes count (auth required)
- `GET /api/items/:itemId/likes/me` - Check if current user liked (auth required)
- `GET /api/items/:itemId/likes/users` - Get users who liked (auth required)

### Comments

- `POST /api/items/:itemId/comments` - Create comment (auth required)
- `GET /api/items/:itemId/comments` - Get all comments (public)
- `PATCH /api/items/comments/:commentId` - Update comment (owner only)
- `DELETE /api/items/comments/:commentId` - Delete comment (owner only)
- `GET /api/items/:itemId/comments/count` - Get comment count (public)

## Technical Details

**Likes Features:**

- Unique constraint on `userId + itemId` prevents duplicates
- Returns `409 Conflict` if already liked
- Validates item existence before creating like
- Includes user aggregation for "who liked" queries

**Comments Features:**

- Full ownership validation for edit/delete operations
- Returns `403 Forbidden` if non-owner attempts modification
- Includes user info (username, avatarUrl) in all responses
- Ordered by creation date (newest first)
- Max length validation (1000 characters)

**Database Schema:**
Both modules use existing Prisma schema with proper relations and indexes.
