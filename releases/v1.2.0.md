# Release v1.2.0 - Real-Time Messaging Improvements

**Release Date**: November 29, 2025
**Version**: 1.2.0
**Release Type**: Feature Release

## 🎯 Overview

This release delivers critical improvements to the real-time messaging system, fixing cache invalidation issues that caused stale unread counts and adding support for conversation-level read status updates. The messaging experience is now truly real-time with instant badge updates, immediate read indicators, and proper data freshness across all navigation scenarios.

## ✨ New Features

### Real-Time Messaging Enhancements

- **Conversation Read Events**: Backend now emits `conversationRead` WebSocket event when entire conversations are marked as read
- **Instant Read Indicators**: Message senders now see blue checkmarks (✓✓) immediately when recipients open conversations
- **Bidirectional Badge Updates**: Both message senders and recipients see badge counts update in real-time without delays

### Cache Invalidation Improvements

- **Explicit Cache Key Invalidation**: Added specific cache key `users:${userId}:messages:unread` to invalidation arrays
- **Fixed Stale Count Bug**: Resolved 60-second cache delay issue where unread counts weren't updating immediately
- **Wildcard Pattern Issue**: Fixed unreliable wildcard pattern matching in Redis cache invalidation

## 🐛 Bug Fixes

### Cache Invalidation

- **Fixed**: `sendMessage()` not invalidating recipient's unread count cache
- **Fixed**: `markConversationAsRead()` not invalidating user's unread count cache
- **Fixed**: Wildcard pattern `users:${userId}:messages:*` not reliably matching specific cache keys

### Real-Time Updates

- **Fixed**: Message badge not updating when navigating to messages list from other pages
- **Fixed**: Conversation page not showing latest messages when opened after receiving notification
- **Fixed**: Read indicators not updating in real-time for message senders

### Data Freshness

- **Fixed**: Stale conversation data when navigating to messages list page
- **Fixed**: Stale message data when entering conversation page
- **Fixed**: Badge count showing incorrect value due to cached unread count

## 🔌 WebSocket Events

### New Events

| Event              | Direction | Description                                              |
| ------------------ | --------- | -------------------------------------------------------- |
| `conversationRead` | Server    | Emitted when all messages in conversation marked as read |

**Payload**:

```typescript
{
  conversationId: string;
  count: number; // Number of messages marked as read
}
```

## 🏗️ Technical Implementation

### Backend Changes

**Updated Services**:

- **MessagesService**: Enhanced `@CacheInvalidate` decorators with explicit cache keys
  - `sendMessage()`: Added `users:${dto.recipientId}:messages:unread` to invalidation
  - `markConversationAsRead()`: Added `users:${userId}:messages:unread` to invalidation

**Cache Strategy**:

```typescript
// Before (unreliable)
@CacheInvalidate((userId: string, dto: SendMessageDto) => [
  `users:${dto.recipientId}:messages:*`
])

// After (reliable)
@CacheInvalidate((userId: string, dto: SendMessageDto) => [
  `users:${dto.recipientId}:messages:*`,
  `users:${dto.recipientId}:messages:unread`, // Explicit key
])
```

### Frontend Changes

**Updated Pages**:

- **`/messages/[id]/page.tsx`**:
  - Added `onConversationRead` listener for real-time read status updates
  - Added `refetchOnMount: "always"` to ensure fresh messages on page load
  - Added `staleTime: 0` to prevent showing cached stale data

- **`/messages/page.tsx`**:
  - Added `refetchOnMount: "always"` to show latest conversation data
  - Added `staleTime: 0` to ensure fresh data when navigating from other pages

**WebSocket Integration**:

```typescript
// Listen for conversation read events
useEffect(() => {
  const unsubscribe = onConversationRead((data) => {
    if (data.conversationId === conversationId) {
      // Mark ALL messages as read in UI
      queryClient.setQueryData(...)
    }
  });
  return unsubscribe;
}, [conversationId, onConversationRead, queryClient]);
```

## 📝 Business Rules

### Message Read Status

- ✅ Messages are marked as read when recipient opens conversation
- ✅ Sender receives `conversationRead` event immediately
- ✅ UI updates read indicators (✓ → ✓✓) in real-time
- ✅ Badge count decrements immediately when messages marked as read

### Cache Behavior

- ✅ Unread count cache has 60-second TTL for performance
- ✅ Cache is explicitly invalidated on message send and conversation read
- ✅ Both wildcard and specific cache keys invalidated for reliability
- ✅ Frontend uses `staleTime: 0` for critical real-time data

### Data Freshness

- ✅ Conversations list always refetches when page mounts
- ✅ Conversation messages always refetch when page opens
- ✅ WebSocket events update UI immediately for users already on pages
- ✅ Navigation from other pages shows fresh data without cache delays

## 🔄 Migration Notes

## 🚀 Deployment

### Prerequisites

- Backend version v1.1.0 or higher
- Frontend with updated conversation page components
- Redis cache server running

### Backend Installation

```bash
# Pull latest code
git pull origin main

# Install dependencies (no new dependencies)
cd swapbuds-backend
yarn install

# Restart application
yarn start:prod
```

### Frontend Installation

```bash
# Pull latest code
git pull origin main

# Install dependencies (no new dependencies)
cd swapbuds-frontend
yarn install

# Build for production
yarn build

# Restart application
yarn start
```

### Cache Considerations

No Redis cache clearing required. The cache will automatically invalidate using the new explicit keys. Existing cached entries will expire naturally within 60 seconds.
