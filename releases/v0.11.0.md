# Release v0.11.0 - Trade Counter-Offers

**Release Date**: November 22, 2024
**Version**: 0.11.0
**Release Type**: Minor Release

## Overview

Comprehensive trade counter-offer system enabling users to negotiate trades by proposing alternative items. Maintains clear negotiation history and provides flexibility during trade discussions.

## Features

### Trade Counter-Offers

- **Alternative Item Proposals**: Propose different items during negotiation
- **Negotiation Messages**: Optional 500-character message with each counter-offer
- **Status Tracking**: PENDING, ACCEPTED, REJECTED, EXPIRED
- **Trade Updates**: Accepting counter-offer updates original trade
- **History**: All counter-offers preserved for audit trail
- **Permissions**: Only trade participants can create counter-offers

### Counter-Offer Workflow

1. User creates counter-offer with alternative item
2. Other party can accept or reject
3. On acceptance: Trade automatically updated with new item
4. Original trade proposal status remains
5. Counter-offer history preserved

## API Endpoints

| Method | Endpoint                                | Description                      |
| ------ | --------------------------------------- | -------------------------------- |
| POST   | `/api/trades/:id/counter-offers`        | Create counter-offer             |
| GET    | `/api/trades/:id/counter-offers`        | Get all counter-offers for trade |
| POST   | `/api/trades/counter-offers/:id/accept` | Accept counter-offer             |
| POST   | `/api/trades/counter-offers/:id/reject` | Reject counter-offer             |

## Technical Implementation

### Database Schema

```prisma
enum CounterOfferStatus {
  PENDING
  ACCEPTED
  REJECTED
  EXPIRED
}

model CounterOffer {
  id                 String              @id @default(cuid())
  status             CounterOfferStatus  @default(PENDING)
  tradeId            String
  createdById        String
  alternativeItemId  String
  message            String?             @db.VarChar(500)
  expiresAt          DateTime?
  createdAt          DateTime            @default(now())
  updatedAt          DateTime            @updatedAt

  trade              Trade               @relation(fields: [tradeId], references: [id])
  createdBy          User                @relation("CounterOffersCreated", fields: [createdById], references: [id])
  alternativeItem    Item                @relation(fields: [alternativeItemId], references: [id])

  @@index([tradeId])
  @@index([status])
}
```

### Services

- **TradesService**: Enhanced with counter-offer operations
  - `createCounterOffer()` - Validate and create counter-offer
  - `acceptCounterOffer()` - Update trade with alternative item
  - `rejectCounterOffer()` - Mark counter-offer as rejected
  - `getCounterOffers()` - List all counter-offers for trade

### DTOs

- **CreateCounterOfferDto**: Validate counter-offer creation
- **CounterOfferResponseDto**: Format with creator and item details

## Business Rules

- ✅ Only trade participants can create counter-offers
- ✅ Counter-offers only valid for PENDING trades
- ✅ Alternative item must belong to counter-offer creator
- ✅ Alternative item must be AVAILABLE
- ✅ Message limited to 500 characters (optional)
- ✅ Accepting counter-offer updates original trade
- ✅ Only non-creator can accept/reject counter-offer
- ✅ Counter-offers can't be edited after creation
- ✅ Expired status reserved for future expiration feature
