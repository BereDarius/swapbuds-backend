# Release v0.11.0 - Trade Counter-Offers

**Release Date:** November 22, 2024
**Type:** Minor Release (New Feature)

## 🎯 Overview

This release introduces a comprehensive trade counter-offer system, enabling users to negotiate trades by proposing alternative items. This enhancement significantly improves the trading experience by providing flexibility and maintaining a clear negotiation history.

## ✨ New Features

### Trade Counter-Offers System

#### Database Schema

- **New CounterOfferStatus Enum:**

  - `PENDING` - Counter-offer awaiting response
  - `ACCEPTED` - Counter-offer accepted, trade updated
  - `REJECTED` - Counter-offer declined
  - `EXPIRED` - Counter-offer expired (future use)

- **New CounterOffer Model:**
  - `id` - Unique identifier (CUID)
  - `status` - Counter-offer status (default: PENDING)
  - `tradeId` - Associated trade
  - `createdById` - User who created the counter-offer
  - `alternativeItemId` - Proposed alternative item
  - `message` - Optional negotiation message (max 500 chars)
  - `createdAt` / `updatedAt` - Timestamps
  - `expiresAt` - Optional expiration date (for future use)

#### API Endpoints

##### 1. Create Counter-Offer

```http
POST /api/trades/:id/counter-offers
Authorization: Bearer <token>
Content-Type: application/json

{
  "alternativeItemId": "item-789",
  "message": "How about this item instead?"
}
```

**Response (201):**

```json
{

  "status": "PENDING",
  "tradeId": "trade-456",
  "createdBy": {

    "username": "john_doe",
    "avatarUrl": "https://..."
  },
  "alternativeItem": {
    "id": "item-789",
    "title": "Alternative Item",
    "description": "A great alternative",
    "condition": "EXCELLENT",
    "category": "ELECTRONICS",
    "images": ["https://..."]
  },
  "message": "How about this item instead?",
  "createdAt": "2024-11-22T10:00:00.000Z",
  "updatedAt": "2024-11-22T10:00:00.000Z",
  "expiresAt": null
}
```

##### 2. Get Trade Counter-Offers

```http
GET /api/trades/:id/counter-offers
Authorization: Bearer <token>
```

**Response (200):**

```json
[
  {
    "id": "counter-offer-123",
    "status": "PENDING",
    "tradeId": "trade-456",
    "createdBy": { ... },
    "alternativeItem": { ... },
    "message": "How about this item instead?",
    "createdAt": "2024-11-22T10:00:00.000Z",
    "updatedAt": "2024-11-22T10:00:00.000Z",
    "expiresAt": null
  }
]
```

##### 3. Accept Counter-Offer

```http
PATCH /api/trades/counter-offers/:id/accept
Authorization: Bearer <token>
```

**Response (200):**
Returns the accepted counter-offer with status "ACCEPTED".

**Side Effects:**

- Counter-offer status updated to `ACCEPTED`
- All other pending counter-offers for the trade are automatically rejected
- Trade is updated with the alternative item
- Notification sent to counter-offer creator

##### 4. Reject Counter-Offer

```http
PATCH /api/trades/counter-offers/:id/reject
Authorization: Bearer <token>
```

**Response (200):**
Returns the rejected counter-offer with status "REJECTED".

**Side Effects:**

- Counter-offer status updated to `REJECTED`
- Notification sent to counter-offer creator

#### Business Logic

**Authorization:**

- Only trade participants (proposer or responder) can create counter-offers
- Only the other party (not the creator) can accept/reject counter-offers
- Trade must be in `PENDING` status to create counter-offers

**Validation:**

- Alternative item must exist and be owned by the counter-offer creator
- Alternative item must have `AVAILABLE` status
- Cannot create counter-offers for non-pending trades
- Counter-offer must be `PENDING` to be accepted/rejected

**Notifications:**

- User receives real-time notification when counter-offer is created
- Counter-offer creator receives notification when accepted/rejected
- Notification types: `TRADE_PROPOSAL`, `TRADE_ACCEPTED`, `TRADE_REJECTED`

**Cache Invalidation:**

- Creating counter-offer: Invalidates trade cache and user's trades cache
- Accepting counter-offer: Invalidates all trades and user's trades cache
- Rejecting counter-offer: Invalidates all trades and user's trades cache
- Getting counter-offers: Cached per trade

## 🔄 Trade Flow Updates

### Original Flow:

1. User A proposes trade (Item A for Item B)
2. User B accepts or rejects

### Enhanced Flow with Counter-Offers:

1. User A proposes trade (Item A for Item B)
2. User B creates counter-offer (Item C instead of Item B)
3. User A accepts or rejects counter-offer
4. If accepted: Trade updates to use Item C
5. If rejected: Original trade remains, negotiation continues

### Multiple Counter-Offers:

- Both parties can create multiple counter-offers
- All counter-offers listed chronologically
- Accepting one automatically rejects all others
- Clear history maintained for each trade
