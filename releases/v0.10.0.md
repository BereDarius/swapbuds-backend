# Release v0.10.0 - Redis Caching System

**Release Date**: November, 2025
**Version**: 0.10.0
**Release Type**: Feature Release

## 🎯 Overview

Comprehensive Redis-based caching system to significantly improve API performance and reduce database load. Features declarative caching decorators, automatic cache invalidation with wildcard patterns, cache warming on startup, and performance monitoring capabilities.

## ✨ New Features

### Declarative Caching Decorators

- **@Cacheable Decorator**: Method-level caching with automatic cache-aside pattern
  - Configurable TTL per method
  - Custom key generation based on method parameters
  - Automatic cache retrieval and population
  - Transparent to business logic
- **@CacheInvalidate Decorator**: Automatic cache invalidation after mutations
  - Wildcard pattern support (`items:*`, `users:${userId}:*`)
  - Multiple key invalidation in single operation
  - Executes after method completion
  - Smart parameter-based key generation

### Cache Infrastructure

- **CacheService**: Core Redis abstraction layer
  - Get/set/delete operations with TTL support
  - Wildcard key deletion with pattern matching
  - Async/await based API
  - Error handling and logging
- **CacheModule**: NestJS module with global availability
  - Exports decorators for easy import
  - Provides CacheService, CacheWarmingService, and CacheMonitoringService
  - Integrates with existing application modules

### Cache Warming

- **CacheWarmingService**: Pre-populates cache on application startup
  - Automatic execution via `OnModuleInit` lifecycle hook
  - Configurable items count and TTL
  - Warms recent items (last 20 by creation date)
  - Warms popular items (top 20 by likes count)
  - Graceful error handling (app starts even if warming fails)
  - Configurable enable/disable flag

### Cache Monitoring

- **CacheMonitoringService**: Tracks cache performance metrics
  - Hit/miss counting per cache key pattern
  - Hit rate calculations
  - Performance stats exposed via REST endpoint
  - Automatic metric tracking via decorators
- **Cache Stats Endpoint**: `/api/cache/stats` returns real-time metrics
  - Hit/miss counts by key pattern
  - Overall hit rates
  - Total operations tracked

### HTTP Caching Interceptor (Optional)

- **HttpCacheInterceptor**: Controller-level HTTP response caching
  - ETag support for efficient bandwidth usage
  - Configurable TTL
  - URL-based cache keys
  - Returns `304 Not Modified` when content unchanged
  - Available but not currently applied to controllers

## 🏗️ Technical Implementation

### New Modules

- **CacheModule**: Global NestJS module for caching infrastructure
- **CacheService**: Core Redis operations service
- **CacheWarmingService**: Startup cache population service
- **CacheMonitoringService**: Performance metrics tracking service
- **@Cacheable**: Method decorator for automatic caching
- **@CacheInvalidate**: Method decorator for cache invalidation
- **HttpCacheInterceptor**: Optional HTTP-level caching interceptor

### Updated Modules

- **ItemsService**: Refactored to use `@Cacheable` and `@CacheInvalidate`
  - `findAll()`, `findByUser()`, `findOne()`: Cached with 5-minute TTL
  - `create()`, `update()`, `remove()`: Invalidate `items:*` and `users:${userId}:*`
- **UsersService**: Refactored to use decorators
  - `getUserProfile()`: Cached with 10-minute TTL
  - `updateProfile()`, `uploadAvatar()`: Invalidate `users:${userId}:*`
- **NotificationsService**: Refactored to use decorators
  - `getUnreadCount()`: Cached with 1-minute TTL
  - `createNotification()`, `markAsRead()`, `markAllAsRead()`: Invalidate `users:${userId}:notifications:*`
- **MessagesService**: Refactored to use decorators
  - `getUnreadCount()`: Cached with 1-minute TTL
  - `sendMessage()`, `markAsRead()`, `markConversationAsRead()`: Invalidate `users:${userId}:messages:*`

### Dependencies

- `ioredis@5.4.2`: High-performance Redis client for Node.js

### Configuration

- `REDIS_PORT`: Redis server port (default: 6379)
- `REDIS_PASSWORD`: Redis authentication password (optional)

## 📝 Business Rules

### Caching Strategy

- ✅ Read operations (GET) are cached with appropriate TTLs
- ✅ Write operations (POST/PATCH/DELETE) invalidate related cache entries
- ✅ Wildcard patterns ensure comprehensive cache invalidation
- ✅ Cache misses automatically populate cache for future requests
- ✅ Decorators inject CacheService automatically into classes

### Cache Key Patterns

- ✅ Items: `items:${id}`, `items:list:${page}:${limit}:all`, `users:${userId}:items`
- ✅ Users: `users:${userId}`
- ✅ Notifications: `users:${userId}:notifications:unread`
- ✅ Messages: `users:${userId}:messages:unread`
- ✅ Wildcard invalidation: `items:*`, `users:${userId}:*`, etc.

### Cache TTLs

- ✅ Items: 5 minutes (300000ms)
- ✅ User profiles: 10 minutes (600000ms)
- ✅ Notification counts: 1 minute (60000ms)
- ✅ Message counts: 1 minute (60000ms)
- ✅ Cache warming: 5 minutes (configurable)

## 🚀 Deployment

### Prerequisites

- Redis server (v6.0 or higher recommended)
- Existing SWAPBUDS backend application (v0.9.0)

### Installation

```bash
# Pull latest code
git pull origin main

# Install dependencies
yarn install

# Ensure Redis is running
redis-cli ping  # Should return PONG

# Restart application
yarn start:prod
```

### Environment Variables

Add/update the following in your `.env` file:

```env
REDIS_HOST=localhost
REDIS_PORT=6379
REDIS_PASSWORD=  # Optional, leave empty if no password
```

### Redis Setup

```bash
# Install Redis (macOS)
brew install redis

# Start Redis
brew services start redis

# Or run Redis manually
redis-server

# Verify Redis is running
redis-cli ping
```

## 📝 Notes

### Cache Warming

Cache warming runs automatically on application startup. To disable:

```typescript
// In cache.module.ts
new CacheWarmingService(cacheService, prisma, { enabled: false });
```

### HttpCacheInterceptor Usage

The HTTP cache interceptor is available but not currently applied. To use it:

```typescript
import { HttpCacheInterceptor } from '@/cache/cache.module';

@UseInterceptors(new HttpCacheInterceptor({ ttl: 300 }))
@Get()
async getData() { ... }
```

### Monitoring Cache Performance

View real-time cache statistics:

```bash
curl -H "Authorization: Bearer YOUR_JWT_TOKEN" http://localhost:3001/api/cache/stats
```
