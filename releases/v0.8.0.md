# Release v0.8.0 - Real-time Features

**Release Date**: November 2024
**Version**: 0.8.0
**Release Type**: Feature Release

## 🎯 Overview

Enhanced notifications system with real-time WebSocket delivery and email notifications, plus user-configurable notification preferences for granular control over notification channels.

## ✨ New Features

### WebSocket Real-time Notifications

- **Real-time Delivery**: Instant notification updates via WebSocket connections
- **Connection Management**:
  - Automatic connection/disconnection handling
  - JWT authentication for WebSocket connections
  - Room-based subscriptions (one room per user)
  - Multiple device support (tracks all active connections per user)
- **Live Events**:
  - New notification events
  - Notification read status updates
  - All notifications marked as read events
  - Notification deletion events
- **Online Status Tracking**: Check if users are currently online and count active connections

### Email Notifications

- **HTML Email Templates**: Beautiful, responsive email templates with consistent branding
- **Automated Emails**:
  - Trade proposals (sent to responder)
  - Trade acceptances (sent to proposer)
  - Trade rejections (sent to proposer)
  - Trade cancellations (sent to responder)
  - Welcome emails (sent to new users)
- **Graceful Degradation**: System continues functioning if email credentials not configured
- **SMTP Support**: Configurable SMTP settings (Gmail default)

### Notification Preferences System

- **Granular Control**: Separate preferences for push (in-app) and email notifications
- **16 Preference Settings**:
  - Email: Trade Proposal, Trade Accepted, Trade Rejected, Trade Cancelled, New Message, New Comment, New Like, New Review
  - Push: Trade Proposal, Trade Accepted, Trade Rejected, Trade Cancelled, New Message, New Comment, New Like, New Review
- **Smart Defaults**: All notifications enabled by default (opt-out model)
- **Automatic Creation**: Preferences auto-created for new users
- **Preference Enforcement**: Notifications only created/sent if user has enabled them

| Event                  | Direction | Description                         |
| ---------------------- | --------- | ----------------------------------- |
| `subscribe`            | Client    | Subscribe to user notification feed |
| `unsubscribe`          | Client    | Unsubscribe from notification feed  |
| `notification`         | Server    | New notification received           |

| `allNotificationsRead` | Server    | All notifications marked as read    |
| `notificationDeleted`  | Server    | Notification deleted                |

## 📝 Business Rules

### WebSocket Authentication

- JWT token required for all WebSocket connections
- Token can be provided via Authorization header or query parameter
- Invalid tokens disconnect the client with error message

### Notification Creation

- Push notifications only created if user has enabled push preference for that type
- Returns `null` if push disabled (graceful handling)
- Real-time WebSocket event emitted immediately after creation

### Email Sending

- Emails only sent if user has enabled email preference for that type
- Email failures logged but don't affect notification creation
- System continues working if SMTP credentials not configured

### Preference Defaults

- All preferences default to `true` (opt-out model)
- Preferences automatically created when first accessed
- Users can update any combination of preferences

## 💡 Usage Examples

### WebSocket Client (React)

```typescript
import { io } from 'socket.io-client';

const socket = io('ws://localhost:3001/notifications', {
  auth: { token: localStorage.getItem('accessToken') },
});

// Subscribe to notifications
socket.emit('subscribe', userId);

// Listen for new notifications
socket.on('notification', (notification) => {
  // Update UI with new notification
  addNotification(notification);
});

// Listen for read status changes
socket.on('notificationRead', ({ notificationId }) => {
  markNotificationAsRead(notificationId);
});

// Cleanup on unmount
return () => socket.disconnect();
```

### Update Preferences

```typescript
// Disable email notifications for trade proposals
await fetch('/api/notifications/preferences', {
  method: 'PUT',
  headers: {
    'Content-Type': 'application/json',
    Authorization: `Bearer ${token}`,
  },
  body: JSON.stringify({
    emailTradeProposal: false,
    pushTradeProposal: true, // Keep push enabled
  }),
});
```

## 🔄 Migration Guide

### For Existing Users

1. Run migrations: `yarn prisma migrate dev`
2. (Optional) Configure email credentials in `.env`
3. Default preferences will be created automatically on first access
4. All existing functionality continues working without changes

### For Frontend Developers

1. Install Socket.io client: `npm install socket.io-client`
2. Implement WebSocket connection with JWT auth
3. Subscribe to notification events
4. Handle real-time notification updates in UI
5. Add notification preferences UI (optional)
