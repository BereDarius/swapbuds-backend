# Release v0.8.0 - Real-time Features

**Release Date**: November 2024
**Version**: 0.8.0
**Release Type**: Feature Release

## Overview

Enhanced notifications with real-time WebSocket delivery, email notifications, and user-configurable preferences for granular control over notification channels.

## Features

### WebSocket Real-time Notifications

- **Instant Delivery**: Real-time notification updates via WebSocket
- **JWT Authentication**: Secure WebSocket connections
- **Connection Management**: Multiple device support, automatic reconnection
- **Room-based Subscriptions**: One room per user for targeted delivery
- **Online Status Tracking**: Check if users are currently online
- **Live Events**: New notifications, read status, deletions

### Email Notifications

- **HTML Templates**: Beautiful, responsive email templates using Handlebars
- **Automated Emails**: Trade proposals, acceptances, rejections, cancellations, welcome
- **SMTP Support**: Configurable SMTP settings (Gmail default)
- **Graceful Degradation**: System continues if email not configured

### Notification Preferences

- **Granular Control**: Separate settings for push (in-app) and email
- **16 Preference Settings**:
  - Email: Trade events, messages, comments, likes, reviews
  - Push: Trade events, messages, comments, likes, reviews
- **Smart Defaults**: All notifications enabled (opt-out model)
- **Auto-creation**: Preferences created for new users
- **Enforcement**: Notifications respect user preferences

## API Endpoints

| Method | Endpoint                         | Description        |
| ------ | -------------------------------- | ------------------ |
| GET    | `/api/notifications/preferences` | Get preferences    |
| PUT    | `/api/notifications/preferences` | Update preferences |

### WebSocket Events

| Event                  | Direction     | Description                    |
| ---------------------- | ------------- | ------------------------------ |
| `subscribe`            | Client→Server | Subscribe to notifications     |
| `unsubscribe`          | Client→Server | Unsubscribe from notifications |
| `notification`         | Server→Client | New notification               |
| `notificationRead`     | Server→Client | Notification read              |
| `allNotificationsRead` | Server→Client | All marked as read             |
| `notificationDeleted`  | Server→Client | Notification deleted           |

## Technical Implementation

### New Modules

- **NotificationsGateway**: WebSocket gateway with JWT auth
- **WsJwtGuard**: Custom WebSocket authentication guard
- **MailModule**: Email configuration with Handlebars templates
- **MailService**: 5 email template methods with graceful error handling

### Database Schema

```prisma
model NotificationPreferences {
  id                    String   @id @default(cuid())
  userId                String   @unique

  // Email preferences (8)
  emailTradeProposal    Boolean  @default(true)
  emailTradeAccepted    Boolean  @default(true)
  emailTradeRejected    Boolean  @default(true)
  emailTradeCancelled   Boolean  @default(true)
  emailNewMessage       Boolean  @default(true)
  emailNewComment       Boolean  @default(true)
  emailNewLike          Boolean  @default(true)
  emailNewReview        Boolean  @default(true)

  // Push preferences (8)
  pushTradeProposal     Boolean  @default(true)
  pushTradeAccepted     Boolean  @default(true)
  pushTradeRejected     Boolean  @default(true)
  pushTradeCancelled    Boolean  @default(true)
  pushNewMessage        Boolean  @default(true)
  pushNewComment        Boolean  @default(true)
  pushNewLike           Boolean  @default(true)
  pushNewReview         Boolean  @default(true)

  createdAt             DateTime @default(now())
  updatedAt             DateTime @updatedAt
}
```

### Integration

- NotificationsService checks preferences before creating notifications
- MailService checks email preferences before sending
- WebSocket gateway emits to online users only
- All services gracefully handle missing preferences

## Business Rules

- ✅ WebSocket connections require JWT authentication
- ✅ Users can only subscribe to their own notification feed
- ✅ Preferences auto-created with defaults for new users
- ✅ Notifications only created if user enabled push preference
- ✅ Emails only sent if user enabled email preference
- ✅ System continues if email server unavailable
- ✅ Multiple devices per user supported
