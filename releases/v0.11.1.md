# Release v0.11.1 - Trade Expiration System

**Release Date:** November 22, 2024
**Type:** Patch Release (Enhancement)

## 🎯 Overview

This patch release introduces an automatic trade expiration system that ensures pending trade proposals don't remain open indefinitely. The system uses scheduled cron jobs to automatically expire trades after a configurable period and sends warning notifications before expiration.

## ✨ New Features

### Automatic Trade Expiration

#### System Behavior

- **Default Expiration:** Pending trades expire after 72 hours (3 days)
- **Warning Notification:** Users receive a notification 24 hours before expiration
- **Automatic Cleanup:** Cron jobs run in the background without manual intervention
- **Status Update:** Expired trades automatically transition to `EXPIRED` status

#### Configuration

Add to your `.env` file:

```bash
# Trade expiration time in hours (default: 72 = 3 days)
TRADE_EXPIRATION_HOURS=72

# Send notification X hours before expiration (default: 24)
TRADE_EXPIRATION_NOTIFICATION_HOURS=24
```

#### Scheduled Tasks

**Expiration Check (Every Hour):**

- Scans for trades that have passed their expiration date
- Updates status from `PENDING` to `EXPIRED`
- Sends expiration notifications to both parties
- Runs at minute 0 of every hour

**Expiration Warnings (Every 6 Hours):**

- Finds trades expiring within the warning window
- Sends reminder notifications to responders
- Helps prevent missed trade opportunities
- Runs at minute 0 past every 6th hour

All trade endpoints now include the `expiresAt` field in responses, showing when the trade will expire if still pending.

#### Notifications

**When Trade Expires:**

- **Proposer:** "Your trade proposal for '{item_title}' has expired"
- **Responder:** "Trade proposal from {username} for '{item_title}' has expired"
- **Type:** `TRADE_CANCELLED`

**24 Hours Before Expiration:**

- **Responder only:** "Trade proposal from {username} expires in {hours} hours"
- **Type:** `TRADE_PROPOSAL`

#### Email Notifications

In addition to in-app notifications, the system now sends email notifications for trade expiration events:

**Trade Expired Email:**

- Sent to both proposer and responder
- Different content based on role (proposer vs responder)
- Includes trade details and link to view trade
- Styled with orange/gray theme for expiration

**Trade Expiring Warning Email:**

- Sent only to responder 24 hours before expiration
- Includes countdown (hours remaining)
- Action-oriented with "Respond to Trade Now" button
- Styled with warning colors (yellow/orange)

Email templates:

- `trade-expired.hbs` - Expiration notification
- `trade-expiring.hbs` - 24-hour warning

## 🔐 Security & Business Logic

### Trade Lifecycle

1. **Creation:** Trade created with `expiresAt` set to 72 hours from now
2. **Active Period:** Trade remains `PENDING`, users can accept/reject/counter-offer
3. **Warning (T-24h):** Responder receives notification
4. **Expiration:** Status changes to `EXPIRED`, both users notified
5. **Post-Expiration:** Trade no longer actionable, archived

### Edge Cases Handled

- ✅ Trade accepted before expiration: `expiresAt` ignored
- ✅ Trade rejected before expiration: `expiresAt` ignored
- ✅ Trade cancelled: `expiresAt` ignored
- ✅ Server downtime: Catches up on restart
- ✅ Timezone handling: All dates stored in UTC
