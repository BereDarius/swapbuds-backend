# Release v0.9.0 - Messaging System

**Release Date**: November, 2025
**Version**: 0.9.0
**Release Type**: Feature Release

## 🎯 Overview

Comprehensive messaging system enabling direct communication between users on the SWAPBUDS platform. Features conversation-based messaging, real-time delivery via WebSocket, read receipts, and full integration with the notification system from v0.8.0.

## ✨ New Features

### Conversation-Based Messaging

- **Direct Messages**: Users can message any other user directly
- **Trade Context**: Optional trade linking for negotiation discussions
- **Smart Conversation Management**:
  - Automatic conversation creation between user pairs
  - User ID normalization prevents duplicate conversations
  - Last message preview with timestamps
  - Unread count tracking per conversation
- **Message Operations**:
  - Send text messages (up to 5000 characters)
  - Retrieve paginated message history
  - Mark individual messages or entire conversations as read
  - Soft delete messages (preserves history)
  - Get total unread count across all conversations

### Real-Time Features

- **WebSocket Message Delivery**: Instant message delivery to online recipients
- **Read Receipts**: Real-time read status updates to senders
- **Typing Indicators**: Infrastructure ready for typing status (not yet actively tracked)
- **Bulk Read Status**: Notify when multiple messages are marked as read
- **Connection Management**: Integrates with existing WebSocket gateway from v0.8.0

### Notification Integration

- **NEW_MESSAGE Notifications**: Automatic notification creation when messages arrive
- **Email Support**: Optional email notifications for new messages (respects user preferences)
- **User Preferences**: Uses `emailNewMessage` and `pushNewMessage` settings from v0.8.0
- **Rich Metadata**: Includes messageId, conversationId, and sender info for deep linking
- **Message Preview**: Shows first 100 characters in notification

## 🔌 API Endpoints

### Messages Controller

All endpoints require JWT authentication (`@UseGuards(JwtAuthGuard)`).

#### `POST /api/messages`

Send a message to another user.

**Request Body**:

```json
{
  "content": "Hey, is your skateboard still available?",
  "recipientId": "user-123",
  "tradeId": "trade-456", // Optional
  "type": "text" // Optional, default: "text"
}
```

**Response**: MessageResponseDto with sender info

#### `GET /api/messages/conversations`

Get all conversations for the authenticated user, sorted by last message time.

**Response**: Array of ConversationResponseDto with:

- Conversation metadata
- Other user info (id, username, avatarUrl)
- Optional trade context
- Unread message count
- Last message preview

#### `GET /api/messages/conversations/:conversationId`

Get paginated messages in a conversation.

**Query Parameters**:

- `page` (optional): Page number (default: 1)
- `limit` (optional): Items per page (default: 50, max: 100)

**Response**:

```json
{
  "messages": [MessageResponseDto],
  "total": 42
}
```

#### `PATCH /api/messages/:id/read`

Mark a specific message as read (recipient only).

**Response**: MessageResponseDto with `isRead: true` and `readAt` timestamp

#### `PATCH /api/messages/conversations/:conversationId/read`

Mark all unread messages in a conversation as read.

**Response**:

```json
{
  "count": 3 // Number of messages marked as read
}
```

#### `DELETE /api/messages/:id`

Soft delete a message (sender only).

**Response**:

```json
{
  "message": "Message deleted successfully"
}
```

#### `GET /api/messages/unread/count`

Get total unread message count across all conversations.

**Response**:

```json
{
  "count": 5
}
```

## 🔌 WebSocket Events

Connect to the NotificationsGateway (`ws://localhost:3001/notifications`) to receive real-time message events.

### Events Emitted to Clients

#### `message`

New message received in a conversation.

**Payload**:

```typescript
{
  id: string;
  content: string;
  type: string;
  senderId: string;
  conversationId: string;
  isRead: boolean;
  readAt: Date | null;
  createdAt: Date;
  sender: {
    id: string;
    username: string;
    avatarUrl: string | null;
  }
}
```

#### `messageRead`

A message has been marked as read.

**Payload**:

```typescript
{
  messageId: string;
  conversationId: string;
}
```

#### `conversationRead`

Multiple messages in a conversation have been marked as read.

**Payload**:

```typescript
{
  conversationId: string;
  count: number;
}
```

#### `messageDeleted`

A message has been deleted.

**Payload**:

```typescript
{
  messageId: string;
  conversationId: string;
}
```

#### `typing`

Typing indicator (infrastructure ready, not yet used).

**Payload**:

```typescript
{
  conversationId: string;
  isTyping: boolean;
  username: string;
}
```

## 🗃️ Database Schema

### Conversation Model

```prisma
model Conversation {
  id                    String    @id @default(cuid())
  user1Id               String
  user2Id               String
  tradeId               String?   @unique
  lastMessageContent    String?
  lastMessageAt         DateTime?
  lastMessageSenderId   String?
  createdAt             DateTime  @default(now())
  updatedAt             DateTime  @updatedAt

  user1     User      @relation("ConversationsAsUser1")
  user2     User      @relation("ConversationsAsUser2")
  trade     Trade?    @relation(fields: [tradeId])
  messages  Message[]

  @@unique([user1Id, user2Id])
  @@index([user1Id])
  @@index([user2Id])
  @@index([tradeId])
}
```

### Message Model

```prisma
model Message {
  id             String    @id @default(cuid())
  content        String
  type           String    @default("text")
  senderId       String
  conversationId String
  isRead         Boolean   @default(false)
  readAt         DateTime?
  isDeleted      Boolean   @default(false)
  createdAt      DateTime  @default(now())
  updatedAt      DateTime  @updatedAt

  sender       User         @relation(fields: [senderId])
  conversation Conversation @relation(fields: [conversationId])

  @@index([conversationId])
  @@index([senderId])
  @@index([isRead])
}
```

## 🔒 Security & Authorization

- **JWT Authentication**: All endpoints require valid JWT token
- **Ownership Validation**: Users can only delete their own messages
- **Conversation Access**: Users can only access conversations they're part of
- **Read Permissions**: Only message recipients can mark messages as read
- **Input Validation**: Strict validation on all DTOs
  - Message content limited to 5000 characters
  - Recipient must exist
  - Cannot message yourself
  - Pagination limits enforced (max 100 per page)

- **Soft Delete**: Messages flagged as deleted, not removed (preserves history)

- **Targeted WebSocket**: Events only emitted to specific users

## 📝 Usage Examples

### Basic Message Flow

```typescript
// 1. Send a message
const response = await fetch('http://localhost:3001/api/messages', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    Authorization: `Bearer ${token}`,
  },
  body: JSON.stringify({
    content: 'Hey, is your skateboard still available?',
    recipientId: 'user-123',
  }),
});

// 2. Listen for real-time messages
socket.on('message', (message) => {
  console.log('New message:', message.content);
  // Update UI
});

// 3. Mark as read
await fetch(`http://localhost:3001/api/messages/${messageId}/read`, {
  method: 'PATCH',
  headers: { Authorization: `Bearer ${token}` },
});
```

### Trade-Related Message

```typescript
// Send message with trade context
await fetch('http://localhost:3001/api/messages', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    Authorization: `Bearer ${token}`,
  },
  body: JSON.stringify({
    content: 'I accept your trade proposal!',
    recipientId: 'user-123',
    tradeId: 'trade-456',
  }),
});
```

## 🐛 Known Limitations

- **Message Types**: Currently only supports text messages (image support planned)
- **Typing Indicators**: Infrastructure ready but not actively tracked
- **Message Search**: No full-text search yet
- **Message Editing**: Not supported (delete and resend)
- **Bulk Operations**: Can't delete entire conversations
- **Group Conversations**: Only supports 1-on-1 conversations
