# v0.13.0 - Multi-Item Trades 🔄

**Release Date**: November 22, 2024  
**Test Coverage**: 475 passing tests

## 🎯 Overview

This release introduces a groundbreaking feature that allows users to propose trades involving multiple items on each side. Users can now create complex trades like "3 books for 2 games" or "vintage record collection for gaming console and accessories."

## ✨ New Features

### Multi-Item Trade Support

#### **Core Functionality**
- ✅ **Multi-Item Proposals**: Create trades with multiple items on each side
- ✅ **Backward Compatibility**: Legacy single-item trades continue to work seamlessly  
- ✅ **Flexible API**: Supports both old format (`itemOfferedId`/`itemRequestedId`) and new format (`itemsOfferedIds`/`itemsRequestedIds`)
- ✅ **Validation**: Comprehensive validation for item ownership, availability, and user permissions

#### **Database Schema Changes**
- ✅ **TradeItem Join Table**: New table to manage many-to-many relationship between trades and items
- ✅ **TradeItemSide Enum**: Distinguishes between offered and requested items
- ✅ **Optional Legacy Fields**: Single-item fields made optional for backward compatibility
- ✅ **Order Support**: Items maintain display order for consistent presentation

#### **API Enhancements**
- ✅ **CreateTradeDto**: Updated to accept arrays of item IDs
- ✅ **TradeResponseDto**: Returns both legacy single-item and new multi-item arrays
- ✅ **Format Validation**: Prevents mixing legacy and new formats in same request
- ✅ **Comprehensive Error Messages**: Clear feedback for all validation failures

## 📊 Technical Details

### Database Migration
```prisma
// New TradeItem model
model TradeItem {
  id        String        @id @default(cuid())
  tradeId   String
  trade     Trade         @relation(fields: [tradeId], references: [id])
  itemId    String
  item      Item          @relation(fields: [itemId], references: [id])
  side      TradeItemSide // OFFERED or REQUESTED
  order     Int           @default(0)
  createdAt DateTime      @default(now())
  
  @@unique([tradeId, itemId])
  @@index([tradeId])
  @@index([itemId])
}

// Updated Trade model
model Trade {
  // Legacy fields (now optional)
  itemOfferedId   String?
  itemOffered     Item?   @relation("TradeItemOffered")
  itemRequestedId String?
  itemRequested   Item?   @relation("TradeItemRequested")
  
  // New multi-item support
  tradeItems      TradeItem[]
}
```

## 🔍 Validation Rules

### Multi-Item Trade Validation
1. **Format Exclusivity**: Cannot mix legacy and new formats in same request
2. **Minimum Items**: At least one item required on each side
3. **Item Existence**: All item IDs must reference existing items
4. **Ownership**: Proposer must own all offered items
5. **Single Responder**: All requested items must belong to same user
6. **Self-Trade Prevention**: Cannot trade with yourself
7. **Availability**: All items must have status `AVAILABLE`
8. **No Duplicates**: Same item cannot appear multiple times in one trade
