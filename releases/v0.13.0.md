# Release v0.13.0 - Multi-Item Trades

**Release Date**: November 22, 2024
**Version**: 0.13.0
**Release Type**: Minor Release

## Overview

Multi-item trade support allowing users to propose trades with multiple items on each side (e.g., "3 books for 2 games"). Fully backward compatible with existing single-item trades.

## Features

### Multi-Item Trade Support
- **Multi-Item Proposals**: Create trades with multiple items on each side
- **Backward Compatibility**: Legacy single-item trades continue working seamlessly
- **Flexible API**: Supports both old format (`itemOfferedId`/`itemRequestedId`) and new format (`itemsOfferedIds`/`itemsRequestedIds`)
- **Comprehensive Validation**: Item ownership, availability, permissions
- **Order Preservation**: Items maintain display order

### API Formats
**Legacy Format** (still supported):
```json
{
  "itemOfferedId": "item-123",
  "itemRequestedId": "item-456"
}
```

**New Format**:
```json
{
  "itemsOfferedIds": ["item-123", "item-456", "item-789"],
  "itemsRequestedIds": ["item-abc", "item-def"]
}
```

### Response Format
Both formats return full item arrays:
```json
{
  "id": "trade-xyz",
  "itemsOffered": [{ "id": "item-123", ... }],
  "itemsRequested": [{ "id": "item-456", ... }],
  "itemOfferedId": "item-123",  // Legacy compatibility
  "itemRequestedId": "item-456"  // Legacy compatibility
}
```

## API Endpoints

All existing trade endpoints enhanced with multi-item support:
- POST `/api/trades` - Create trade (accepts both formats)
- GET `/api/trades/:id` - Get trade (returns both formats)
- GET `/api/trades` - List trades (returns both formats)

No new endpoints - fully backward compatible.

## Technical Implementation

### Database Schema
```prisma
enum TradeItemSide {
  OFFERED
  REQUESTED
}

model TradeItem {
  id        String        @id @default(cuid())
  tradeId   String
  itemId    String
  side      TradeItemSide
  order     Int           @default(0)
  createdAt DateTime      @default(now())
  
  trade     Trade         @relation(fields: [tradeId], references: [id], onDelete: Cascade)
  item      Item          @relation(fields: [itemId], references: [id])
  
  @@unique([tradeId, itemId])
  @@index([tradeId])
  @@index([itemId])
}

model Trade {
  // Legacy fields (optional for backward compatibility)
  itemOfferedId   String?
  itemOffered     Item?         @relation("TradeItemOffered", fields: [itemOfferedId], references: [id])
  itemRequestedId String?
  itemRequested   Item?         @relation("TradeItemRequested", fields: [itemRequestedId], references: [id])
  
  // New multi-item support
  tradeItems      TradeItem[]
}
```

### Services
- **TradesService**: Enhanced with multi-item logic
  - `createTrade()` - Handles both single and multi-item formats
  - `validateTradeItems()` - Ownership and availability checks
  - `createTradeItems()` - Populate TradeItem join table
  - `populateTradeItems()` - Load items for responses

### DTOs
- **CreateTradeDto**: Updated to accept item arrays (both formats validated)
- **TradeResponseDto**: Returns both legacy fields and item arrays

## Business Rules

- ✅ Cannot mix legacy and new formats in same request
- ✅ All offered items must belong to proposer
- ✅ All requested items must belong to responder
- ✅ All items must have AVAILABLE status
- ✅ Minimum 1 item per side
- ✅ Items can't be duplicated within same side
- ✅ Legacy single-item trades fully supported
- ✅ Counter-offers work with multi-item trades
