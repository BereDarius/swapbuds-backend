# Release v0.10.2 - Schema Validation & ItemCategory Enum

**Release Date**: November 22, 2025
**Version**: 0.10.2
**Release Type**: Patch Release

## Overview

Critical schema validation fixes removing incorrect fields (price, location on items) and implementing proper ItemCategory enum for type-safe data validation.

## Features

### Schema Validation Fixes
- **Removed Price Fields**: Eliminated price/minPrice/maxPrice (swap-only platform, not buying/selling)
- **Removed Item Location**: Location belongs to User, not Item
- **Fixed ItemCondition Enum**: Added missing EXCELLENT condition
- **Type Safety**: All enums now imported from @prisma/client

### ItemCategory Enum
- **Database Enum**: Created ItemCategory enum in Prisma schema
- **Type Safety**: Changed Item.category from String to enum
- **Safe Migration**: Preserves existing category data
- **Valid Categories**: ELECTRONICS, CLOTHING, BOOKS, TOYS, SPORTS, COLLECTIBLES, HOME, OTHER

## API Endpoints

No new endpoints - this is a schema validation release.

### Breaking Changes for Frontend
**Item category now requires enum values:**
- Before: `category: "Electronics"` (any string)
- After: `category: "ELECTRONICS"` (must match enum)

**Removed fields:**
- `price`, `minPrice`, `maxPrice` (not applicable for swaps)
- `location` on items (use `user.location` instead)

## Technical Implementation

### Database Schema
```prisma
enum ItemCategory {
  ELECTRONICS
  CLOTHING
  BOOKS
  TOYS
  SPORTS
  COLLECTIBLES
  HOME
  OTHER
}

model Item {
  category  ItemCategory  // Changed from String
  // Removed price-related fields
  // Removed location field
}
```

### Migration
**Migration**: `20251122140341_add_item_category_enum`
- Safe CASE statement migration preserves data
- Added index on items.category
- No data loss

### Updated Files
- DTOs updated to use Prisma enums (CreateItemDto, ItemResponseDto, ItemFilterDto)
- Removed price/location from ItemFilterDto
- Updated Swagger documentation
- All test fixtures use proper enums

## Business Rules

- ✅ Item category must be one of 8 valid enum values
- ✅ No price fields (swap-only platform)
- ✅ Location comes from user profile, not item
- ✅ ItemCondition includes all 6 values (NEW, LIKE_NEW, EXCELLENT, GOOD, FAIR, POOR)

## Migration Notes

### Database Migration
```bash
# Apply migration
yarn prisma migrate deploy

# Regenerate Prisma client
yarn prisma generate
```

### Frontend Changes Required
Update item creation/editing to use enum values:
```typescript
// Valid categories (uppercase)
category: 'ELECTRONICS' | 'CLOTHING' | 'BOOKS' | 'TOYS' | 'SPORTS' | 'COLLECTIBLES' | 'HOME' | 'OTHER'

// Valid conditions
condition: 'NEW' | 'LIKE_NEW' | 'EXCELLENT' | 'GOOD' | 'FAIR' | 'POOR'

// Valid statuses
status: 'AVAILABLE' | 'IN_TRADE' | 'TRADED' | 'REMOVED'
```
